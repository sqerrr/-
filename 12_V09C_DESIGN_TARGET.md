# v0.9C DESIGN TARGET — ELITE HEARTBEAT / CHAIN GRAMMAR

**Status:** target brief only. No v0.9C gameplay code is implemented in this archive. The executable remains v0.9B.

## Goal

Prove the two defining pillars before more balance/content work:

1. **Frequent adaptive Elites are the heartbeat of the run.**
2. **Catalysts create visible, modular causal combinations between Phenomena.**

## Preserve from v0.9B

Finite world, minimap, POI infrastructure, boss foundation, presentation bridge, canonical CombatShape, HP bars, damage numbers, offscreen Elite/Boss indicators, reduced normal-projectile direction.

## Replace/reopen

- Elite pacing/director;
- adaptation telemetry and logic;
- XP reward grammar;
- Phenomenon acquisition cadence;
- Resonance/general-stat model;
- mutations;
- Catalysts and eventually Chain topology.

## Minimal sandbox

- 4 test Phenomena: Ember / Frost / Orbit / Mortar;
- 6 Catalyst operator families: Carrier / Trigger / Transducer / Fork / Memory / Feedback;
- 3–4 Elite chassis, 3 protocols, 5 adaptive responses;
- high/frequent Elite cadence with recovery windows;
- POI guardians additive, not replacements for free-roaming Elite pressure.

## Non-goals

- final HP/DPS balance;
- final enemy roster;
- final world geometry;
- final number of Phenomena/Catalysts;
- universal-slot Chain implementation;
- automated “best build” testing.

## Design invariant

A successful run should not be explainable as “I kept upgrading one weapon until mutation and ignored the Chain.”

A successful Elite encounter should be explainable as “it reacted to what I was doing; I changed how I played or how the Chain was arranged; that created an opening.”
