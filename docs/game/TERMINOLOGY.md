# Терминология спецификации

В русской версии намеренно сохраняются некоторые английские **технические идентификаторы**, чтобы текст напрямую соответствовал JSON, коду, логам и инструментам. Это не означает, что такие слова обязаны остаться в финальном UI игры.

| Термин в спеках | Рабочее русское значение | Примечание |
|---|---|---|
| Skill | активный навык / боевая сущность | Позднее может получить лорное название, например «Феномен» |
| Catalyst | катализатор / связующий камень | Стоит между соседними Skills и изменяет передачу контекста |
| Chain | активная цепочка | 6 Skill-слотов и 5 промежуточных Catalyst-слотов в текущей гипотезе |
| Reserve | резерв | Небольшой запас компонентов для быстрой перестройки |
| Mutation | мутация | Крупная развилка поведения конкретного Skill |
| Law | Закон | Legendary-правило, способное менять правила системы шире одного Skill |
| Elite chassis | шасси элитки | Базовый поведенческий тип элитного врага |
| affix | аффикс | Добавочная механическая характеристика элитки |
| adaptive affix | адаптивный аффикс | Вероятностный ответ мира на реальный паттерн игрока |
| state | состояние | Машинный словарь взаимодействий: `mark`, `field`, `embed` и т. п. |
| proc | срабатывание эффекта | В формулах и ID остаётся `proc` |
| Power | обычный аддитивный процент силы | Один из основных прозрачных числовых bucket'ов |
| Amplification | усиление | Отдельный аддитивный внутри себя multiplicative bucket |
| Director | директор | Система, управляющая давлением/спавном/адаптациями по правилам |
| POI | точка интереса | Активность на карте, обычно меняющая риск, RNG или развитие билда |
| high-roll | очень удачный ран/ролл | Намеренно допускается как часть roguelike-фантазии |

## Правило локализации

- **В пользовательском UI системные термины должны быть по возможности полностью локализованы на русский.** Английские `payload`, `proc`, `state`, `bridge` и т.п. допустимы в debug/коде, но не должны быть необходимы для понимания карточки/камня.
- В `data/catalog_v0_1.json`, code ID, telemetry и debug UI идентификаторы должны оставаться стабильными и английскими.
- Спецификация может писать «элитка», «навык», «катализатор» в прозе, но кодовые сущности `SkillDefinition`, `CatalystDefinition`, `SpawnDirector` и состояния в обратных кавычках не переводятся.


## Дополнение после v0.8

Для Catalyst tooltip предпочтительно описывать не абстрактный внутренний термин, а фактическую причинность на текущей паре. Пример: “Если левый феномен убил врага, следующий справа с шансом повторяется” вместо “kills charge relay repeat”. В расширенном/debug tooltip можно отдельно показать стабильные code IDs.
