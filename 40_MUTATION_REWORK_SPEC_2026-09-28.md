## 1. Диагноз (что сломано и почему)

### 1.1 Системные причины слабости
1. **Мёртвые триггеры.** Метку (`markUntil`) пишут только `returner_execution`, `sentry_relay`, `sentry_hunter_battery` и легаси. Все условия «по цели с меткой» в соло-сборке не срабатывают никогда: `rail_spot`, `rail_sky_lance`, `mortar_spotter`, `mortar_hunter_pass`, `arc_ground`.
2. **Статусы без эффекта.** Горение (`igniteUntil`) не наносит урона нигде → `fan_burn` = 0. `displacedUntil` не влияет на движение врагов (`enemyRuntimeSystem` читает только frozen/chill) → `tether_bind`, `tether_lock`, «теряют ход» = текст.
3. **Штраф больше выгоды.** `rail_gun` (стреляет раз в 2 цикла, сбрасывает количество), `rail_rack` (×0.78 без отдачи), `tether_hook` (площадь ×0.42, лимит 2 цели), `fan_tight` (1 клинок вместо N), `fan_wide`, `frost_rim` (×0.48 внутри), `toxic_distilled`, `cleaver_guillotine`, `orbit_saw` (медленнее вращение), `mass_rail` (узкий), `sentry_rail` (оверкилл). Ярус I-штрафы тянутся сквозь II и III (проверки `st.mutation === …`).
4. **Описания без кода:** `mass_recoil` «сильнее» (урона нет), `mass_snowball` «за каждого врага», `mass_cargo` «тела», `mass_avalanche`, `toxic_plume` «тянется следом», `toxic_plague_road` «постоянно», `toxic_septic_bloom` «цепная реакция», `returner_phoenix` «взрыв пересечения», `returner_execution` «цепляется», `frost_front` «расширяющееся», `frost_glacier_heart` «замораживает», `gravity_singularity` «накапливает… уязвимее», `gravity_prison` «не тянется», `orbit_many` «каждое наносит меньше», `fan_tight` «веер».
5. **Ярусы II/III без выбора:** у каждого корня ровно один ребёнок и один апофеоз → окна II/III всегда из одной карточки; «брать то же самое» неизбежно.
6. **Бесполезные условия в толпе:** `arc_capacitive` («если целей не хватило на прыжки» — в толпе никогда), `arc_closed_loop` (бьёт первую цель, которая уже мертва), `arc_cage` («повторные попадания» — цепь не бьёт цель дважды за каст), `toxic_contagion` (`max()` с уже имеющимся ядом = 0), `toxic_corrosive` (только связанные/щитовые/рядом с Бастионом), `toxic_reactive` (нужен контроль/горение, которого у тумана нет).
7. **Лаборатория искажает:** толпа насыщается (~700 HP/s, всё умирает на подходе), шасси элиты случайно (Призма/Пастух/Жнец/Выводок меняют урон), герой бессмертен (барьер = 0), нет вражеских снарядов (перехват = 0).

### 1.2 Перевыполняющие (элитный DPS vs база, t240/t420)
`orbit_outbound→comet→phoenix` (толпа ×1.7–2.0, элита ×4.4–7.8), `sentry_relay` линия (×2.2–5.9: каждый выстрел метит, следующий расходует метку ≈×1.73), `rail_execution_line` ×5.2, `rail_lattice` ×6.6 (центральный узел двойной, большое тело накрывают 5–6 узлов), `mortar_gravity_field` ×5 (удержание элиты в зоне), `gravity_dragnet` ×5.5 (одна цель бьётся тремя якорями), `cleaver_rift_hook` ×2.2 (разлом на каждый повтор).

### 1.3 Учёт количества (факт кода)
| Феномен | Во что превращается доп. количество | Проблема |
|---|---|---|
| rail_spear | доп. лучи (`projectileCount`) | `rail_gun` выбрасывает количество |
| shard_fan | клинки, min(5) | `fan_tight`=1, `fan_wide`=max(3,n) — теряют количество |
| mortar_bloom | удары min(3) | `cluster`=3, `carpet`=5, `hunter_pass`=3 — теряют количество |
| chain_arc | прыжки: 4 + (count−1) + **сырая кратность без лимита** + min(3,⌊q/2⌋) + countBonus + countAdd | не входит в общий бюджет +3 |
| orbit_blades | лезвия 3+(count−1)+кратность+min(3,⌊q/2⌋), 2..12 | **игнорирует countBonus/countAdd**, нет общего бюджета |
| sentry | турели: своя формула, clamp 1..5, живых ≤6 | отдельная формула |
| frost_ring, cleaver, toxic_mist, mass_driver, tether_drag | игнорируется | у секача мёртвый цикл доп. взмахов (`multiplicityFor`=0, оси нет) |

### 1.4 Учёт крита / урона по элитам (факт кода)
Крит бросается на **каждый** вызов `damage()` для источников с runtime навыка (касты, выстрелы турелей, лезвия, снаряды, отложенные удары, **токсичные поля**). **Без крита и без `eliteDamage`:** `fire_field` (в т. ч. ледяные поля кратера/фронта), `arc_field`, `toxin_dot`, `wound_dot`, `septic_cut`, `thermal_shock`, `backdraft`. Флаг «крит» в событиях — эвристика `actual > scaledBase·1.55`, а не факт броска.

### 1.5 Турели и катализаторы (факт кода)
Вся связь идёт через **позицию турели**, не через выстрел: турель — carrier + area (дважды: круг 0.7 и `sentry_placement` 0.42 → два события area на турель), каждый выстрел даёт `contact` в точке турели; path выстрела не пишется. Как A турель может вести только **carrier** (≤3 срабатывания, дедуп по турели) и **collapse** (≤3). Как B: полезная нагрузка «запекается» в `construct.power` на весь срок жизни; trail в турель — до 6 полных кастов турели. Компенсации частоты выстрелов нет, кроме дедупа carrier.

## 2. Цели и критерии приёмки

### 2.1 Метрики (лаборатория, 3 сида, L22@t240 и L33@t420)
- **Роль** каждой мутации объявляется в данных: `crowd` (убитый HP/с в толпе), `elite` (DPS по нейтральной элите) или `guard` (снижение получаемого урона героем).
- **Ярус I:** ≥ +15% по своей роли относительно базы; ни одна метрика не ниже ×0.75 базы; ни одна мутация не «чистый даунгрейд» (обе метрики < ×1.0).
- **Ярус II:** ≥ +12% по роли относительно родителя (без огранки).
- **Ярус III:** итог линии по роли ×1.7–2.6 к базе; **ни одна линия > ×3.0**; разброс трёх апофеозов одного феномена по общей метрике ≤ ×1.8.
- **Между феноменами:** соло-TTK элиты (`balance_elite_duel`) разброс ≤ ×2.5 (сейчас ×3.0–4.6).
- **Честность текста:** каждое утверждение описания мутации и огранки подкреплено кодом (регрессия, см. §7).
- **Катализаторы:** каждая мутация сохраняет ≥1 рабочий сигнал на активацию; нет пустых трасс (`rail_gun`); возвратный путь `returner_carousel` существует; выстрелы турели дают path/contact у цели (§5).
- `npm test` зелёный; детерминизм по сиду сохранён.

### 2.2 Не-цели
- Не трогаем Quantity/кратность как ось силы (решение 36_OWNER_CORRECTION + D5), не вводим «налог на залп».
- Не меняем зеркала соперников (эхо элит используют `mutation: null`), кроме пересчёта `rivalConcentration` при смене `baseDamage` (урон соперника по герою должен остаться прежним).
- Не меняем экономику ядер мутаций и порядок окон прогрессии.

## 3. Системные изменения

### S1. Огранки (facets) на ярусах II и III
**Данные** (`content/definitions.ts`):
```ts
export type MutationFacetId = 'edge' | 'reach' | 'hunt' | 'ward';
export const mutationFacets: Record<MutationFacetId, { name; short; tier2: FacetStats; tier3: FacetStats }>;
// FacetStats: powerMul?, radiusMul?, rangeMul?, durationMul?, eliteDamage?, crit?, armor?, maxHp?, moveSpeed?, barrierOnCast?
```
| Огранка | Ярус II | Ярус III | Примечание |
|---|---|---|---|
| **Острота** (`edge`) | урон ×1.15 | урон ×1.20 | через `powerBucket` |
| **Охват** (`reach`) | радиус ×1.12, дальность ×1.10, длительность ×1.10 | ×1.15 / ×1.12 / ×1.15 | **без количества** (D5) |
| **Охота** (`hunt`) | +20% урона по элитам, +5% крит | +25%, +7% | через `skill.eliteDamage`/`skill.crit`-канал |
| **Оплот** (`ward`) | броня +6, макс. HP +15, скорость +3% | броня +8, HP +25, скорость +4%, барьер +4 за каст | только пока феномен в **активном** слоте (D2) |

- Огранки II и III складываются (можно выбрать одну и ту же дважды).
- **Окно II/III:** карточки = та же мутация × 3 огранки из 4 (выбор 3 из 4 через `port.randomInt`, детерминированно). Отказ (refusal) — по-прежнему только ярус I.
- **Состояние:** `SkillRuntime.facetUpgrade: MutationFacetId | null`, `SkillRuntime.facetApotheosis: MutationFacetId | null`.
- **Предложение:** `MutationOffer.facets?: MutationFacetId[]` параллельно `choices`; `MutationChoiceSystem.choose(index)` пишет огранку соответствующего яруса.
- **Применение:** единая функция `mutationFacetStats(st)` (сумма/произведение двух ярусов); читается в `powerBucket`, `skillRadius`, `skillRange`, `persistentDuration`, `EnemyDamageModifierSystem` (elite/crit), герой — агрегатор `mutationWard(stat)` по активным слотам (по образцу `catalystAttunement`), проводка в броню / maxHp / скорость движения / барьер.
- **maxHp:** при снятии феномена из активного слота бонус снимается, текущее HP обрезается до нового максимума.
- **Возврат ядер** (`buildLoadoutSystem.refundMutationCores`) очищает и огранки.
- **Сериализация:** `canonicalStateSerializer` добавляет оба поля. `BenchmarkLoadout` получает `mutationFacets?`.
- **UI** (`main.ts`, окно мутации): заголовок — мутация, подзаголовок — «ОГРАНКА: …», строка чисел; планировщик показывает огранки у феномена; бейдж огранки в слоте.

### S2. Встроенный бонус яруса I («райдер»)
Каждый корень получает явный числовой бонус в тексте и в коде, чтобы ни один выбор яруса I не был пустым (таблица §4). Штрафы корней больше не превышают выгоду.

### S3. Правдивые статусы
- **Горение:** реальный DoT `burn_dot`: 35% урона поджигающего попадания в секунду, 2.6 с, обновление по максимуму, не суммируется. Без крита, с `eliteDamage` владельца.
- **Смещение (`displacedUntil`):** замедляет движение — обычные ×0.35, элиты ×0.6, босс не подвержен. Используется связками Якоря и гравиполями (проверить, что `mortar_gravity_field` не станет сильнее: см. §4 миномёт).
- **Метки:** мутации, которые читают метку, **сами её ставят** (см. §4) — никаких условий, которые соло не выполняются.

### S4. Атрибуция полей и DoT, крит
- Поля и DoT, созданные феноменом героя, несут `ownerSkill`: получают множители предметов, `eliteDamage` и огранку «Охота» владельца; **крит не бросается** для тиков полей/DoT (включая токсичные поля — единообразно). Источник в журнале урона — имя феномена (`frost_ring:field`, `chain_arc:field` и т. д.), чтобы телеметрия считала вклад мутаций честно.
- Флаг крита в событиях = факт броска (вернуть из `resolve()`), не эвристика.
- Ледяные поля (`mortar_crater`, `frost_front`) перестают подписываться как `fire_field`.

### S5. Единый бюджет количества
- Таблица «во что превращается количество» становится данными (`phenomenonCountConversion`), каждый каст читает её, а не собственную формулу.
- Общий лимит доп. копий +3 (кратность + ⌊Quantity/2⌋) — для **всех** мультишот-феноменов, включая дугу и орбиту.
- Орбита начинает учитывать `countBonus` и `countAdd`.
- Мутации, которые раньше «выбрасывали» количество, **конвертируют** его: `rail_gun` → урон одного луча, `fan_tight` → клинки в одну точку, `mortar_cluster/carpet/hunter_pass` → доп. зоны.
- Немультишот-феномены (иней, секач, туман, вал, якорь) по-прежнему не получают копий; мёртвый цикл секача удаляется.

### S6. Турели: выстрел как единица катализатора + компенсация частоты (D4)
- Каждый выстрел турели героя пишет в трассу активации **path** (турель → цель) и **terminal/contact в точке цели**; позиция турели остаётся carrier/area.
- `phenomenonChoreography.sentry.emits` += `path`, `terminal` → турель как A открывает **source / trail / reverse** (пересчитать и обновить число совместимых пар в 39 и регрессиях).
- Бюджет: катализатор, сработавший от выстрелов, ограничен **3 срабатываниями на привязку**, а полезная нагрузка от выстрела идёт с масштабом ×0.6 («турельная отдача»).
- Двойное событие area на турель устраняется (один круг).
- **Компенсация количества турелей:** урон выстрела героя ×min(1, √(2 / живых_турелей)) — 2 турели = 100%, 4 = 71% (сумма 2.83), 6 = 58% (сумма 3.46). Число живых — только турели героя.
- Реакции элит на число попаданий (Выводок: клон каждые 10 попаданий; Пастух: «сгусток» при >9 попаданий/с) считают выстрелы турелей и лезвий орбиты весом 0.5.

### S7. Лаборатория `balance_mutation_matrix` (до правок баланса)
- Толпа: волна 18 мобов раз в 2 с (сейчас 10 раз в 2.5 с — насыщение).
- Элита: `--chassis` (по умолчанию нейтральное шасси без реакции на урон), аффикс `none`, фиксированная редкость.
- Режим `--mortal`: герой смертен, метрика «получено урона/с» для роли `guard`; источник вражеских снарядов (кольцо стрелков) для перехватов орбиты.
- Варианты с огранками (`base / I / I>II·facet / I>II>III·facet`), колонка роли и флаги нарушения критериев §2.1, флаг `--assert`.
- Метрика катализаторов: срабатывания/мин и «пустые активации» по каждой мутации.

## 4. Мутации по феноменам (что сделать)

Обозначения: **Ок** — оставить (правка только текста/чисел); **Усилить** — та же идея, починка чисел/условия; **Переделать** — новая механика под то же имя/id. Все id сохраняются.

### 4.1 Цепная дуга (слабый феномен — подтянуть базу)
- **База:** дальность прыжка 4.2 → 5.0; если в радиусе есть элита, цепь **может ударить её дважды за каст** (второй раз — с текущим затуханием); общий бюджет количества (S5). После правок пересчитать `baseDamage` по дуэли (цель — войти в разброс ×2.5).
- `arc_forked` (I, толпа) — **Усилить:** прыжок 5.5; райдер «+3 прыжка, затухание 0.93».
- `arc_cage` (II) — **Переделать:** поле рождается на **каждой элите** в цепи и на **последнем узле**, а не при «повторном попадании за 2.2 с». Поле атрибутируется дуге.
- `arc_hunting_storm` (III) — **Усилить:** импульсы могут бить уже задетую элиту.
- `arc_capacitive` (I, элита) — **Переделать (убрать бесполезное условие):** каждый каст заканчивается **2 возвратными импульсами ×0.52** в самую «жирную» цель цепи; оставшиеся неизрасходованные прыжки добавляют импульсы (до 4).
- `arc_relay` (II) — **Ок.**
- `arc_living_circuit` (III) — **Усилить:** без турелей/якорей узлом сети считается сам герой (разряд ×0.65 в 2 ближайшие цели).
- `arc_ground` (I, элита) — **Переделать:** цепь **начинается** с цели с наибольшим HP в радиусе (элита приоритетна), первый удар ×1.45; метка/застрявший снаряд — дополнительный приоритет, а не условие.
- `arc_groundloop` (II) — **Ок.**
- `arc_closed_loop` (III) — **Переделать:** петля замыкается на **самую жирную живую** цель пути ×1.55, срабатывает и при пути из одной цели.
